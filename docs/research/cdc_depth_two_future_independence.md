# Future-independence

**Criterion.** A rank/certificate system is future-independent iff, at S1 creation, A/B ranks use only R's registered current allowance and split_1; either branch may later discharge, split under an applicable local rule, or remain unresolved; later work never rewrites an earlier rank/certificate; carried obligations are unchanged; each actual transition descends; and no final leaf count, height, identities, or guard outcomes are inputs.

## Result: PASS for the registered allowance rule

1. A and B both receive rank 1 from R rank 2 before any later choice.
2. If A is selected, C/D receive rank 0 from A and split_2 only. The symmetric rank logic would permit B, although the executable geometry recognizes only registered A split_2.
3. R/A/B creation records remain immutable.
4. split_1 remains the same `9 -> 6` certificate.
5. split_2 yields `6 -> 5`, retaining B's weight 3.
6. No leaf count or final layout occurs in rank calculation.

The initial allowance 2 is a current policy/capability bound, not knowledge that A will split or that three leaves will result. A rank-zero branch cannot refine and returns `UNRESOLVED`/fallback-required if its theorem cannot be discharged. This proves future independence only within the declared depth-two capability, not indefinite composition.
