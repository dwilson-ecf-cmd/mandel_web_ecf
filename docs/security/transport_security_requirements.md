# Требования к защищённому транспорту

Будущий транспорт обязан использовать TLS 1.3 или более строгий профиль, аутентифицированное шифрование, предпочтительно `TLS_AES_256_GCM_SHA384`, запрет downgrade до TLS 1.2, отсутствие открытого fallback, отсутствие прикладных данных до завершения аутентифицированного рукопожатия, запрет 0-RTT для изменяющих Рабочую область намерений, проверку сертификата или закреплённой идентичности сервиса и доступность channel binding для сопряжения и повторной аутентификации. Реализация должна применять зрелую криптографическую библиотеку. Этот этап не добавляет TLS, AES, сертификаты, сокеты или слушатели.
