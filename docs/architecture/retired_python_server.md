# Снятие с эксплуатации унаследованного Python-сервера

## Решение

Статус: `RETIRED`.

Владелец проекта явно разрешил снять с эксплуатации только компонент с историческими путями `server.py` и `legacy/servers/server.py`. Удаление выполняется коммитом `Retire legacy Python render server`; точный объект восстановления определяется командой `git log --all -- legacy/servers/server.py`.

## Историческая ответственность

Сервер запускал HTTP-процесс с пустым адресом привязки (все интерфейсы) на порту `8000`, выводил локальный адрес `localhost` для пользователя, обслуживал статические файлы из текущего каталога и реализовывал маршрут `/api/render`. Маршрут разбирал параметры изображения и строил командную строку для платформенно совместимого `render_engine`. Формирование команды через оболочку из параметров запроса создавало риск внедрения команды и не соответствует действующей модели доверия.

Компонент перестал быть авторитетным: он не входит в CMake, не импортируется и не запускается тестами, не требуется среде выполнения, совместимой границе рендерера, воспроизведению эталонных результатов или созданию артефактов. Авторитетные переносимые контракты находятся в `shared/`, модульное выполнение — в `runtime/`; будущая сетевая композиция должна быть утверждена отдельно и не наследует этот сервер автоматически.

Корневой UI исторически обращается к `/api/render`, но нативная сборка и проверка его не запускают. После снятия сервера этот маршрут не обслуживается; UI сохраняется без перенаправления как отдельная совместимая поверхность.

## Сохранность и восстановление

Размер перед удалением: `1281` байт. SHA-256 перед удалением: `81fa70a1a47321a4b122b0048f72ce2c3c9422f55a6d30a69d51394f7733f214`.

Git является архивом исходного содержимого. Для просмотра или восстановления без переписывания истории следует найти последний коммит с файлом через `git log --all -- legacy/servers/server.py`, затем использовать `git show <commit>:legacy/servers/server.py` либо восстановить его в отдельной ветви. Полный исходный текст здесь намеренно не воспроизводится.

Разрешение и статус `RETIRED` относятся только к Python-серверу. Они сами по себе не разрешали удалять иные компоненты. C++-сервер и комплект иностранных программ позднее получили отдельное разрешение, зафиксированное собственными записями; рендереры, UI, носители, совместимые слои, `CDC.pdf` и исследовательские материалы им не охвачены.
