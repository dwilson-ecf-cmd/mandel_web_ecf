# Аудит знаний автономных рендереров

## Решение

Проверены полные тексты исторических `render.cpp` и `render_engine.cpp`. Статус аудита: готовность подтверждена; элементов `UNRESOLVED` нет. Значимое современное поведение покрыто контрактами и замороженными тестами. Остальные свойства классифицированы как `HISTORICAL_ONLY`, поскольку относятся к небезопасной оболочке, неподдерживаемым экспериментальным формулам, прежним палитрам либо фиксированным путям, а не к обязательству совместимости. История Git и сохранённые BMP/видео удерживают происхождение.

## Инвентаризация обязанностей

| Обязанность | Историческое поведение | Покрытие | Основание |
|---|---|---|---|
| Аргументы `render.cpp` | именованные `--width`, `--height`, `--zoom`, `--cx`, `--cy`, `--iter`, `--formula`, `--palette`, `--out`, `--zpow`, `--cpow`, `--cr`, `--ci`; отсутствует строгая проверка | `HISTORICAL_ONLY` | современный контракт задания заменяет CLI, синтаксис не является API |
| Аргументы `render_engine.cpp` | позиционные mode/zoom/center/formula/palette/iterations/seconds | `HISTORICAL_ONLY` | прежний launcher снят; будущие клиенты не наследуют позиционный ABI |
| Значения по умолчанию | 800 × 600, 150 итераций, центр −0,75 + 0i, zoom 1; HD 1920 × 1080; видео 854 × 480, 30 fps, 5 секунд | `CAPTURED_BY_DOCUMENTATION` | значения полностью записаны здесь; медиа сохраняет примеры, продуктовый контракт их не фиксирует |
| Область и координаты | scale = 4/zoom, поправка aspect; выборка по `x/width`, `y/height`, без включения правой/верхней границы | `CAPTURED_BY_DOCUMENTATION` | современный `fractal_job_spec` задаёт область явно; прежняя дискретизация намеренно не считается совместимостью |
| Mandelbrot | z = 0, c = точка; квадратичная ветвь и настраиваемые степени в первом файле | `CAPTURED_BY_RUNTIME` | `fractal.formula.mandelbrot.v1`, числовой и вычислительный сокеты |
| Julia | z = точка; в engine c = −0,7 + 0,27015i, в первом файле c задаётся `cr`,`ci` | `CAPTURED_BY_RUNTIME` | `fractal.formula.julia.v1` и сериализованные параметры |
| Binary64 | `double`, `std::complex<double>`, `pow`, `norm` | `CAPTURED_BY_TEST` | идентичность Binary64 и тесты числового сокета фиксируют современную арифметику |
| Условие выхода | проверка квадрата модуля `> 4`; внутренние точки получают max_iter/чёрный | `CAPTURED_BY_TEST` | замороженные поля Mandelbrot/Julia и классификация выхода |
| Дополнительные формулы | Burning Ship, Tricorn, Phoenix, Perpendicular, Newton, Sierpinski triangle/carpet, обобщённые степени | `HISTORICAL_ONLY` | не утверждены как продуктовые формулы; непроверенные ветви не переносятся скрыто |
| Палитры | две несовместимые реализации fire/ocean/neon/dstep; magma, grayscale, rainbow; BGR-запись | `HISTORICAL_ONLY` | старые функции не являются стабильным контрактом; исторические BMP/MP4 сохраняются, современный raster имеет замороженные пиксели |
| Формирование поля | циклы по пикселям, OpenMP `parallel for`, динамическое расписание engine | `CAPTURED_BY_RUNTIME` | `fractal.compute.scalar.v1`, serial и thread-pool scheduler с эквивалентностью |
| Анализ поля | отсутствует | `CAPTURED_BY_RUNTIME` | ограниченная цепочка анализаторов добавляет авторитетную ответственность |
| BMP | 54-байтовый BMP v3, 24-bit BGR, выравнивание строк до четырёх байт, положительная высота, нулевые поля разрешения | `CAPTURED_BY_TEST` | `encoder.bmp.v3`, замороженные BMP-суммы и размеры |
| Растеризация | escaped окрашен по числу шагов, bounded чёрный | `CAPTURED_BY_TEST` | авторитетный raster и замороженные пиксели обоих формульных заданий |
| Публикация | прямой `ofstream`, без транзакции и надёжной проверки ошибок | `CAPTURED_BY_RUNTIME` | транзакционный artifact sink намеренно заменяет прямую запись |
| Имена результатов | `render.bmp`, `render_hd.bmp`, `frames/frame_%04d.bmp`, `render.mp4` | `HISTORICAL_ONLY` | файловые имена не являются современным ABI; сами носители сохранены |
| Анимация | удаление/создание `frames`, zoom × 1,05 на кадр, вызов ffmpeg H.264 yuv420p | `CAPTURED_BY_DOCUMENTATION` | алгоритм описан здесь и виден в сохранённых кадрах/MP4; оболочка и ffmpeg не переносятся |
| Диагностика и прогресс | практически отсутствуют; ошибки не передаются | `CAPTURED_BY_RUNTIME` | результаты, прогресс, отмена, манифест и статусы среды выполнения |
| Платформа | C++/OpenMP, POSIX shell, `rm`, `mkdir`, `ffmpeg`, локальная файловая система | `HISTORICAL_ONLY` | непереносимые предположения сняты; чистый CMake не зависит от них |
| Память | `vector` владеет целым буфером, ручные смещения | `CAPTURED_BY_RUNTIME` | scoped memory и явные представления field/pixel buffer |
| Ошибки | `stoi`/`stod`, `ofstream`, `system` без полной проверки; возможны выход за argv и переполнение размеров | `CAPTURED_BY_DOCUMENTATION` | ограничения зафиксированы как причина снятия, но дефекты не воспроизводятся |
| Совместимый рендерер | отдельный `server/renderer/` и C++-адаптер | `CAPTURED_BY_COMPATIBILITY_SURFACE` | остаётся на месте и не зависит от автономных файлов |
| Воспроизводимость | прежние программы не имели манифеста | `CAPTURED_BY_TEST` | реестр, формула, Binary64, scheduler, field/pixels/BMP и manifest identities заморожены |

## Карта авторитетной замены

| Наследуемая ответственность | Авторитетная замена |
|---|---|
| Математика Mandelbrot | `fractal.formula.mandelbrot.v1` |
| Математика Julia | `fractal.formula.julia.v1` |
| Арифметика Binary64 | `fractal.numeric.binary64.v1` |
| Генерация поля | `fractal.compute.scalar.v1` |
| Последовательное и параллельное выполнение | `fractal.scheduler.serial.v1`, `fractal.scheduler.thread-pool.v1` |
| Анализ поля | ограниченная цепочка анализаторов |
| Растеризация | `raster.native.iteration-bgr8` |
| BMP | `encoder.bmp.v3` |
| Публикация | транзакционный artifact sink |
| Воспроизводимость | замороженные идентичности, поля, пиксели, BMP и манифесты |

## Решение о дополнительных фикстурах

Новых фикстур не требуется. Старые размеры, CLI, палитры, дополнительные формулы, имена файлов и видеоконвейер не являются утверждённой совместимостью. Значимое современное поведение уже фиксируется платформенно независимыми тестами Mandelbrot и Julia; историческая визуальная продукция остаётся неизменной. Добавление теста старого поведения ошибочно превратило бы снятую реализацию в новый контракт.
