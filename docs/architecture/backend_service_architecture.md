# Архитектура серверных служб

Логические службы могут сначала находиться в одном процессе, однако сохраняют границы владения:

- **Workspace service** проверяет намерения, применяет редуктор, хранит состояние и выпускает снимки; в ней нет арифметики фрактала.
- **Runtime-control service** преобразует принятое поколение в ограниченное задание среды и сообщает жизненный цикл; в ней нет участников и GUI.
- **Worker service** исполняет единицы работы через существующие формулу, число, вычисление и планировщик.
- **Preview service** публикует ограниченные производные предварительного просмотра.
- **Analysis-delivery service** проецирует типизированные записи анализа в сводки и подробности.
- **Artifact service** владеет историей и публикацией артефактов, не принимает произвольные клиентские пути.
- **Participant/session service** сопоставляет будущие сессии устойчивым участникам и присутствию.
- **Administration service** предоставляет только локальные продуктовые операции управления.

Адаптер транспорта располагается снаружи семантического контракта. Ни служба Workspace, ни адаптер не обходят сокетируемую цепочку `formula → numeric → compute → scheduler → analysis → raster → encoder → artifact`.
